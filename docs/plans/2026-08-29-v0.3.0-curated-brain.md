# Plan: v0.3.0 — The Curated Brain

Date: 2026-08-29
Status: proposed (units land on `develop`; release via gitflow at the end)
Theme: the brain gains its curated corpus (IA-documents), a lifecycle
(AutoCapture TTL), and self-service hygiene (KG delete, logical export).

## Background

The 0.2.x arc closed every loop: corpus imports, visible scope, agent homes,
loop-closers, fleet cutover, CI publishing. What the instance *lacks* now:

1. **The curated half of the two-store model is empty in practice.** The
   Doctrine tier exists (`ijima doctrine ingest`, `POST /doctrine`,
   idempotent upsert-by-id) but was built for the seed-pack only. The
   company's actual curated corpus — `IA-documents` (595 `.md`, 18 MB:
   PULSE distillations, RABBIT_HOLE dives, per-project docs, arxiv
   syntheses) — is invisible to every fleet agent whose workspace doesn't
   have it checked out.
2. **Unbounded AutoCapture growth.** ~264 rows/day burst, 0.6 GB/yr — bytes
   are fine, *signal density* is not. Explicit/Doctrine persist; chatter
   should age out.
3. **Hygiene gaps:** no KG-delete (blocks the 21 misplaced Kaiizen rows),
   `ijima export` opens the DB directly and loses the LOCK race to the
   running daemon.

## Non-goals (0.4 candidates)

Satellites/federation, CRDT tombstone bridge, `turns:batch`, scheduled
mining (WS5), Block↔memory promotability. WAL compaction = spike note in
the release notes, not code.

## Units

### U1 — `/doctrine` honors `?namespace=`

The one gap that matters: `/doctrine` writes to the fixed global
`DOCTRINE_NAMESPACE`, readable by *every* principal on the instance —
wrong visibility for IA-internal strategy. Exact precedent: the 0.2.1 KG
fix (`POST /kg/triples?namespace=`).

- `POST /doctrine?namespace=<ns>` → upsert-by-id semantics in that ns;
  admin gate unchanged; **default (no param) stays global** (backward
  compatible with the seed-pack flow).
- Client: `ingest_doctrine_in(url, token, entry, ns)`.
- CLI: `ijima doctrine ingest --namespace <ns>`.
- Tests (route-level, admin + non-admin + default-ns + custom-ns).

### U2 — markdown driver script (pre-pass approach, operator-endorsed)

The Rust CLI stays minimal (`--namespace` from U1 is the only new flag);
walking/synthesis lives in a stdlib-python driver, `scripts/ingest-markdown.py`:

- Walk a source tree; skip `--exclude` patterns (repeatable) and
  non-`.md` files. Copy qualifying files to a staging dir, flattened,
  each wrapped in synthesized frontmatter when absent:
  `id = doct_<hash12(relpath)>` (stable across re-runs so edits upsert
  and additions append), `project` = first path segment, `topic` =
  second; explicit frontmatter stays authoritative when present.
- One `ijima doctrine ingest --dir <staging> --namespace <ns>` call per
  run. `--dry-run` prints the plan (files, ids, excludes) without
  touching the daemon.
- No size policy in code: the one 650 KB+ monster (pre-depth-limit
  artifact) is excluded by name; nothing else approaches it.

### U3 — the IA-documents run (ops, not code)

- **Two target namespaces** (operator decision 2026-08-29):
  - **`ns_ia_doctrine`** — the reports + general repo-oriented documents:
    `RESEARCH_REPORTS/`, `Anima/`, `Mingot/`, `Amari/`, `CONTRACTS/`,
    `Mishima/`, `Minuet/`, `IA/`, top-level docs.
  - **`ns_ia_arxiv`** — `ARXIV_REPORTS/` (external literature syntheses,
    different signal density; may earn different retention later).
    `ARXIV_REPORTS_archive/` skipped by default; the one pre-depth-limit
    ~660 KB synthesis excluded by name from the live set.
  - Both walls: memberships `lucien` + all `pi-IA-*` hosts (same
    scripted pattern as the fleet cutover); `lucien-kaiizen` explicitly
    NOT a member. Dedicated walls — not the shared capture home —
    because the curated corpus has a re-ingest/upsert lifecycle, unlike
    the wall's append-only captures.
- Run from the workstation where the corpus repo lives (the report
  apparatus host); rate limiter stays on (ingest backoff since U1).
  Verification: per-ns census, sample wake-up/search queries, re-run =
  no-op, Kaiizen-principal scope probe (no `ns_ia_*` rows).
- **Cadence (operator decision 2026-08-29):** a daily morning timer at
  ~08:30, ingesting the previous day's reports *before* the 09:00 pulse
  fires — the report-writing agents access the memory too, so their
  sessions start with yesterday's corpus already retrievable. The
  driver's stable-path ids make every run a no-op except additions and
  edits. Timer lives beside the report apparatus (the corpus repo is
  local there); daemon reached over the tailnet.
- **Least privilege for the timer:** U1's `/doctrine` gate is ADMIN —
  too broad for an unattended cron. Add `DOCTRINE_WRITE` capability;
  route accepts ADMIN **or** DOCTRINE_WRITE; mint a dedicated
  `research-ingest` principal carrying only that. (U1b, small.)
- Optional (the RABBIT_HOLE_2026-08-29_Reports ask): the driver can
  also emit KG index triples (`<repo> covered_by <doct_id>`) — the
  "standing index" becomes queryable knowledge. Deferred unless cheap
  on the day.

### U4 — AutoCapture TTL sweeper

- Daemon background task: daily sweep deletes `source = AutoCapture`
  rows older than `autocapture_ttl_days` (default 30; 0 disables).
  Explicit/Doctrine/import rows are never touched — tier-based, not
  age-based, for everything but chatter.
- Config knob in daemon config; sweep counts logged (journal evidence
  for the soak log).
- Tests: seeded old/new rows per tier → only old AutoCapture swept;
  config off → no-op.

### U5 — KG delete route

- `DELETE /kg/triples?id=<percent-encoded>` (admin), client method,
  CLI. Unblocks the operator's Kaiizen cleanup (21 triples + 36 entities
  in `ns_lucien-kaiizen_private` from the 0.2.0 namespace-blind import).
- Tests: delete-then-404, non-admin 403, KG-census reflects.

### U6 — logical export through the daemon

- `GET /export?namespace=<optional>` (admin): streaming JSONL, one
  memory per line + trailing counts; works against the running daemon
  (no LOCK conflict — this is the API path, not `open_persistent`).
- CLI `ijima export` rewritten to use it (`--url --token
  [--namespace] [--out]`).
- Restore story documented honestly: v1 export = extractable corpus
  (verification + offline analysis + compliance); restore-from-export =
  documented jq→curl loop in the runbook. The mirror remains the
  primary restore path (drill-proven).

### U7 — the contemplative loop (closes the write→remember→reflect→write circle)

A fourth IA-research organ: a daily **contemplation session**,
timed after the morning ingest (~08:45) and before the 09:00 pulse.
Prompt shape: Ijima wake-up (essentials + fresh doctrine) + the last
24h of memory deltas (recent activity across the walls) + a
randomness seed fetched from the Phys.org/ScienceX newswire or the
Quanta Magazine front page (curl the front page, pick headlines). The
session writes one document — working name `CONTEMPLATION_<date>.md`
in `RESEARCH_REPORTS/` — which the *next* morning's ingest captures.
The hippocampus reads its own cortex and writes back.

- Rides the existing IA-research harness (a prompt + shell commands;
  no Ijima server code required — deltas via existing search/stats
  routes; add a `?since=` browse convenience only if the prompt needs
  it).
- Scope note: the document itself is IA-research territory (prompt
  authored there); Ijima's part is the loop plumbing already built in
  U1–U3. If the reflection output earns a namespace of its own later
  (`ns_ia_contemplations`), the same driver handles it.

## Sequencing

U1 → U1b → U2 → U3 (needs both) → U4/U5/U6 in any order; U7 lands
with U3's cadence (it depends on the morning ingest existing). All land on `develop`
as individual PRs; release train (release branch → main → tag → backmerge)
after U3's run is verified in the soak log and U4's first sweep is
observed. Default-features `cargo check` ×4 crates before tagging
(standing policy).

## Risks

- Ingest volume (595 files) is trivial next to the 14.5k-row imports —
  embedder load bounded, rate limiter + backoff already proven.
- TTL sweeper deletes data by design: tier-gated to AutoCapture only;
  Explicit saves (the deliberate ceiling) are untouchable. First sweep
  observed in ops-log before the release tag.
- Namespace-scoped doctrine adds a visibility seam: U3's membership
  script is the enforcement point — verify with a Kaiizen-principal
  probe (expect: no `ns_ia_doctrine` rows in scope) before calling U3
  done.
