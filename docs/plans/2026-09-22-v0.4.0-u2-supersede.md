# Unit 2 — Supersede mechanism (the ritual becomes a mechanism)

**Depends on:** Unit 1 (evidence-grade fields on `Memory`/`MemoryRecord`).
**Followed by:** Unit 4 (wake-up stratified composition composes with this).

## Purpose

RABBIT_HOLE_2026-09-22_Ijima §1: corrections work today only as a
choreography — a manual 0.8 save that ties the wrong memory's importance
and wins the recency tiebreak. Any correction arriving by any other path
loses silently, because `ORDER BY importance DESC, created_at DESC` never
lets recency close an importance gap. This unit makes correction structural:
saving a memory that declares `supersedes: <target_id>` links the pair,
and superseded memories are excluded from wake-up, search, and browse —
regardless of tier arithmetic. Superseded rows stay recallable by id
(visible fossils, not deletions). Operator decision (2026-09-22):
supersede-exclusion only — no decay, no derived rank (0.5 design fork).

## Contracts

### `Memory` struct — add after `citations`, before `created_at`

```rust
    /// Correction link (v0.4.0): the id of the memory this one supersedes
    /// ("this replaces that"). Set once at save time; the server writes
    /// the inverse link onto the target atomically with the insert.
    /// Chains forward only (A ← B ← C); re-superseding a superseded
    /// memory is rejected — supersede the successor instead.
    #[cfg_attr(feature = "serde", serde(default))]
    pub supersedes: Option<String>,
    /// Inverse correction link, written by the server: the id of the
    /// memory that superseded this one. Exclusion queries filter on this.
    #[cfg_attr(feature = "serde", serde(default))]
    pub superseded_by: Option<String>,
    /// When the supersede link landed (unix seconds), for audit.
    #[cfg_attr(feature = "serde", serde(default))]
    pub superseded_at_unix: Option<i64>,
```

### `MemoryRecord` — mirror all three (`#[serde(default)]` each), wire
`from_memory`/`into_memory` both directions. Also add a `#[serde(default)]`
`superseded_by`/`superseded_at_unix` — the linking UPDATE below writes them
onto existing rows, and older rows must still deserialize.

### `backend_surreal.rs` — linking inside `store_memory`

After the dedup check and record construction, before the `.create(...)`:

```rust
        // Supersede linking (v0.4.0): a save declaring `supersedes`
        // writes the inverse link onto its target in the same logical
        // operation. Rejections: absent target (NotFound-equivalent),
        // cross-namespace target (NotFound — recall is ns-scoped),
        // already-superseded target (Conflict — chains go through the
        // successor), self-supersede (Conflict).
        if let Some(target_id) = &memory.supersedes {
            if target_id == &memory.id.0 {
                return Err(IjimaError::conflict("memory cannot supersede itself"));
            }
            let target_key = (MEMORIES_TABLE, memory_key(ns, &MemoryId(target_id.clone())));
            let existing: Option<surrealdb::types::SerdeWrapper<MemoryRecord>> =
                self.db.select(target_key).await.map_err(store_err)?;
            let Some(mut target) = existing else {
                return Err(IjimaError::not_found(format!(
                    "supersede target {} not found in this namespace",
                    target_id
                )));
            };
            if target.superseded_by.is_some() {
                return Err(IjimaError::conflict(format!(
                    "supersede target {} is already superseded (by {}) — supersede the successor instead",
                    target_id, target.superseded_by.clone().unwrap_or_default()
                )));
            }
            let now = std::time::SystemTime::now()
                .duration_since(std::time::UNIX_EPOCH)
                .map(|d| d.as_secs() as i64)
                .unwrap_or_default();
            target.superseded_by = Some(memory.id.0.clone());
            target.superseded_at_unix = Some(now);
            let _: Option<surrealdb::types::SerdeWrapper<MemoryRecord>> = self
                .db
                .update(target_key)
                .content(surrealdb::types::SerdeWrapper(target))
                .await
                .map_err(store_err)?;
        }
```

(If `IjimaError` lacks `not_found`/`conflict` constructors with these
shapes, use the closest existing constructors — `duplicate` exists; check
`ijima-core/src/error.rs` — and map to 404/409 in `api.rs`'s existing
`IjimaError → ApiError` conversion. Add variants only if genuinely absent.)

### Exclusion filters — three queries

- Wake-up (`ORDER BY importance DESC, created_at DESC LIMIT $lim` block):
  add `AND superseded_by = NONE` to the WHERE clause.
- Search (`ORDER BY score DESC` block): same addition.
- Browse/list (`ORDER BY importance DESC, created_at DESC LIMIT` near the
  top of the file): same addition.

`recall_memory` (by id) does NOT filter — superseded rows return with
their links. `check_duplicate` does NOT filter (a correction of identical
content is still a dup — corrections must say something new).

## Tests (enumerate exactly)

`ijima-server` integration-style tests following the existing backend/api
test patterns:

1. `supersede_links_both_directions` — save A; save B with
   `supersedes: Some(A.id)` → B stored; recall A shows
   `superseded_by == Some(B.id)` and `superseded_at_unix.is_some()`;
   recall B shows `supersedes == Some(A.id)`.
2. `superseding_absent_target_rejects` — save B with `supersedes:
   Some("mem_nonexistent")` → store error (not-found class); B not stored.
3. `superseding_already_superseded_rejects` — A ← B; attempt C with
   `supersedes: Some(A.id)` → conflict-class error. Then C with
   `supersedes: Some(B.id)` succeeds (chains through the successor).
4. `self_supersede_rejects` — conflict-class error.
5. `wakeup_excludes_superseded` — seed a namespace with A (importance 0.9,
   superseded) and B (importance 0.5, fresh); wake-up returns B, not A.
6. `search_and_browse_exclude_superseded` — same seed; search matching
   A's content and the browse listing both omit A; recall by id returns it.
7. `supersede_is_namespace_scoped` — A exists only in namespace X; save in
   namespace Y with `supersedes: Some(A.id)` → not-found-class rejection.

`ijima-core` unit test:

8. `supersede_fields_default_none` — the Unit-1 legacy JSON (plus Unit 1's
   fields) deserializes with all three link fields `None`.

## Constraints

- No new crates; no TTL/sweeper changes; no ranking-order changes.
- The linking UPDATE must happen inside `store_memory` before returning
  the id — a save that fails its supersede checks stores nothing.
- Serde: `#[serde(default)]` on all new record fields (legacy rows).
- api.rs route-table doc comment gains `| POST | /memories (supersedes) |`
  context — update the `store_memory` row's doc line only if a natural
  place exists; do not restructure the table.
