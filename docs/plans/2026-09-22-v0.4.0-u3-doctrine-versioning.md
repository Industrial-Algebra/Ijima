# Unit 3 — Doctrine versioning, rollback, and ingest validation (direction B + A-slice)

**Depends on:** Unit 2 (shared `Memory`/`MemoryRecord` field patterns; lands after it).
**Followed by:** Unit 4 (wake-up stratification composes with `revision`).

## Purpose

Direction B: doctrine is the maximum-blast-radius tier (RABBIT_HOLE_2026-09-22
§2 — the trust-ladder inversion), yet ingest today is delete-then-store:
every corpus update silently destroys the prior body. This unit archives
versions, gives every doctrine row a client-visible `revision`, restores
one-command rollback, and adds cheap static stance-directive validation
(A-slice) whose warnings surface in the ingest response for the PR reviewer.

`DoctrineVersion` (define beside the `Store` trait in `ijima-core/src/store.rs`,

```rust
/// An archived revision of a doctrine entry (direction B, v0.4.0).
#[derive(Debug, Clone, PartialEq)]
#[cfg_attr(feature = "serde", derive(serde::Serialize, serde::Deserialize))]
pub struct DoctrineVersion {
    /// The doctrine doc id (memory id in the doctrine namespace).
    pub doc_id: String,
    /// 1-based revision number, monotonic per doc.
    pub version: u32,
    /// The archived body.
    pub content: String,
    /// SHA-256 hex of the body, for cheap diffing.
    pub content_hash: String,
    /// Unix seconds when this version was archived.
    pub archived_at_unix: i64,
    /// Is this the currently-active version? Exactly one is, after any
    /// ingest or rollback; transiently none during the write itself.
    pub active: bool,
}
```

### `backend_surreal.rs` — version storage

New table constant `const DOCTRINE_VERSIONS_TABLE: &str = "doctrine_versions";`
Key layout: `doctrine_versions`, record key
`format!("{ns}_{doc_id}_v{n}")` via the file's existing key-style helper
(`memory_key` pattern). Implement the three methods:

- `archive_doctrine_version`: recall the live row (absent → error
  not-found class). Count existing version rows for `(ns, doc_id)` → `n`.
  Store a `DoctrineVersion` row with `version: n + 1`, the live row's
  content/hash, `active: false`. Return `n + 1`. (First archive of a doc
  ingested before v0.4.0 is version 1 — the pre-versioning body.)
- `list_doctrine_versions`: SELECT the doc's rows `ORDER BY version ASC`.
- `activate_doctrine_version`: fetch version `to` (absent → not-found
  class); rewrite the live memory row: content = version body, `revision =
  Some(to)`, content-hash recomputed, embedding re-embedded if an embedder
  is configured (reuse `embed_for`), `created_at` untouched; mark version
  `to` active and every other version of the doc inactive (UPDATE their
  `active` field — a targeted `SET active = $a WHERE doc_id = $d AND
  version != $v` style query is fine).

### `api.rs` — ingest archives + revision stamp + warnings + routes

In `ingest_doctrine`, replace the delete-then-store block with:

1. Recall the existing row (same ns, id). If present AND content differs:
   `let v = store.archive_doctrine_version(...)` → new revision = `v + 1`.
   If present and content identical: return the existing id unchanged
   (preserves today's idempotency — and note the dedup-by-content path
   below still applies).
2. If no existing row: revision = 1.
3. Store (or re-store) the memory with `revision: Some(n)` and
   `evidence: EvidenceGrade::Observed` + one citation
   `{ kind: CitationKind::Report, locator: <the request's source path if
   DoctrineRequest carries one, else the doc id> }` (doctrine bodies are
   Git-reviewed artifacts — observed with citation). Keep the existing
   check_duplicate early-return for byte-identical content under other ids.
4. Response becomes `DoctrineIngestResponse { id: String, revision: u32,
   warnings: Vec<String> }` (was `IdResponse`).

New routes (admin or doctrine:write, same gate as ingest; rollback
admin-ONLY — reverting the shared baseline is the operator's call):

```rust
.route("/doctrine/versions", get(list_doctrine_versions))
.route("/doctrine/rollback", post(rollback_doctrine))
```

Handlers take `Query<DoctrineDocQuery>` (`{ namespace: Option<String>, id: String }`);
`rollback_doctrine` takes `Json<DoctrineRollbackRequest> { id: String, to: u32 }`
plus the same `?namespace=` rules as ingest. `list_doctrine_versions`
returns `Json<Vec<DoctrineVersion>>` — for the global wall requires ADMIN
or DOCTRINE_WRITE; for other walls MEMORY_READ + resolve_ns.

### `doctrine.rs` — stance scan (pure, testable)

```rust
/// A-slice ingest validation (direction A, v0.4.0): cheap static scan of
/// a doctrine body for dose-dependent stance/persona directives — the
/// poisoning signature from the 2026-09 incident. Advisory: warnings
/// surface in the ingest response for the PR reviewer; doctrine remains
/// PR-reviewed, never auto-blocked.
pub fn stance_warnings(body: &str, prior_body: Option<&str>) -> Vec<String> {
```

Rules (each warning a one-line string, prefixed `stance:`):
- Marker regex set (case-insensitive): `you must`, `you always`, `you
  never`, `you are`, `act as`, `adopt the persona`, `maintain the tone`,
  `embody`. Count total matches. Per 1000 characters of body: if density
  ≥ 5, warn with the density value.
- Accretion: when `prior_body` is Some, if marker count grew by ≥ 50% AND
  the new count ≥ 15, warn that stance directives accreted across this
  revision (include both counts).
- Length dose: body > 12,000 chars AND density ≥ 3 → warn that a long,
  stance-dense body is the accretion pattern from the incident.

Plain `char_indices`/manual scanning or `str::match_indices` per phrase —
NO new crates (no `regex` dependency).

   `revision == Some(2)`; `list_doctrine_versions` returns one archived
   version (body A, version 1, active false).
6. `doctrine_reingest_identical_is_noop` — ingest body B again → same id,

7. `doctrine_rollback_restores_body` — rollback to 1 → recall shows body A
   with `revision == Some(1)`; version 1 active, version row 2 (created as
   the live-row archive on the rewrite) inactive or the live row simply
   carries A — assert `list_doctrine_versions` shows exactly one ACTIVE
   version, and it is version 1's body.
8. `doctrine_ingest_response_carries_warnings` — ingest a stance-dense
   pathological body → 200 with a non-empty `warnings` vector.
9. `wakeup_doctrine_entries_carry_revision` — after the two ingests,
   wake-up's `doctrine` section includes doc X with `revision == Some(2)`.

## Constraints

- No new crates (no `regex` — manual scanning).
- Rollback is ADMIN-only. Ingest gates unchanged.
- `created_at` of the live row survives rollback untouched.
- Do not alter U2's supersede semantics; doctrine versioning is orthogonal
  (Git-versioned tier versions itself through ingest, not supersede links).
