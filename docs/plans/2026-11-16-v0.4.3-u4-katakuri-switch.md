# v0.4.3 U4 — The Katakuri switch: production embedder + parity gate in CI

## Unit

The shipped configuration moves from `embeddings-candle` to
`embeddings-katakuri`: production's model-ecosystem layers (hub fetch,
weight validation, tokenization) route through Katakuri; candle stays
the compute engine (Katakuri never computes — its README is law).
`hf-hub` and `tokenizers` leave the production dependency tree. The
bit-for-bit parity acceptance (PR #140) is what makes this a
configuration change rather than a semantics change — identical
embeddings, no re-embed, comparable ledger similarity data.

The parity gate enters CI so the guarantee is continuous, not
ritual-memory: any drift between the compute paths (a candle bump, a
katakuri bump — exactly the dependabot churn class) fails CI at PR
time instead of at production.

**Depends on:** nothing (rides the 0.4.3 train beside U1–U3).
**Followed by:** the 0.4.3 release train.

### `.github/workflows/ci.yml`

Add a second job after the existing build job (keep the existing job
byte-identical; add only the new job and nothing else — triggers
come from the workflow level, unchanged):

```yaml
  parity:
    runs-on: ubuntu-latest
    timeout-minutes: 25
    steps:
      - uses: actions/checkout@v4
      - name: Install Rust toolchain
        uses: dtolnay/rust-toolchain@stable
      - name: Cache cargo registry
        uses: actions/cache@v4
        with:
          path: |
            ~/.cargo/registry
            ~/.cargo/git
            target
          key: parity-cargo-${{ runner.os }}-${{ hashFiles('Cargo.lock') }}
      - name: Cache model downloads
        uses: actions/cache@v4
        with:
          path: |
            ~/.cache/katakuri/hub
            ~/.cache/huggingface
          key: parity-models-v1
      - name: Run embedding parity acceptance
        env:
          KATAKURI_TEST_PARITY: "1"
        run: |
          cargo test -p ijima-server \
            --features 'embeddings-candle embeddings-katakuri' \
            --test embedding_parity -- --ignored 2>&1 | tail -20
```

Notes for the implementer: the test target self-gates
(`#![cfg(all(feature = "embeddings-candle", feature = "embeddings-katakuri"))]`)
and the test self-skips without `KATAKURI_TEST_PARITY=1`; both are
satisfied above. The first run downloads two ~90 MB models (candle's
hf-hub cache at `~/.cache/huggingface`, Katakuri's content-addressed
cache at `~/.cache/katakuri/hub`); the model cache step makes that a
once-per-runner cost. If the workflow's existing job already defines
a cargo-cache step whose key format you can mirror for consistency,
mirror it — the cache shapes above are the contract, the key naming
may match house style.
