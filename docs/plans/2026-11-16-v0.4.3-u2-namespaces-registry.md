# v0.4.3 U2 — The namespaces registry: walls as addressable objects

## Unit

Walls are currently implicit string prefixes — discoverable only by
root probing `/status`. This unit makes them queryable objects: a
per-principal `GET /namespaces` route listing every wall the caller's
visible search spans, with counts, kind, and deployment-declared
descriptions. The dormant org walls (1–2 rows) become visible as
near-empty — the system's census exposed to everyone, not just root.

**Depends on:** U1 (shares the WallConfig plumbing pattern; the
`app_with_walls` seam).
**Followed by:** the 0.4.3 train.

### `api.rs` — the registry

**Enumeration (refactor, DRY):** the `scope=visible` branch of
`search_memories` currently inlines the wall enumeration (own private
+ `global` + member walls + `ns_import_*`). Extract exactly that into:

```rust
/// The walls a principal's `scope=visible` search spans (U2: also
/// powers `GET /namespaces` — the listing and the search must never
/// disagree about what "visible" means).
async fn visible_walls(
    principal: &AuthPrincipal,
    store: &dyn Store,
) -> Result<Vec<NamespaceId>, ApiError>
```

The search branch calls it (behavior byte-identical: same order —
sorted, deduped).

**Route + types:**

```rust
#[derive(Serialize)]
struct NamespaceEntry {
    namespace: String,
    /// `private` | `shared` | `global` | `import` — inferred from the
    /// slug pattern (see kind_of), never stored.
    kind: &'static str,
    memories: usize,
    /// From the deployment's `[[namespaces]]` declarations, when present.
    description: Option<String>,
}

async fn list_namespaces(
    principal: AuthPrincipal,
    Extension(store): Extension<Arc<dyn Store>>,
    Extension(walls_cfg): Extension<Arc<WallConfig>>,
    Query(q): Query<NamespaceListQuery>,
) -> Result<Json<Vec<NamespaceEntry>>, ApiError> {
    if !principal.0.may(MEMORY_READ) {
        return Err(ApiError::Forbidden);
    }
    // ?all=true (admin) spans every wall in the store; the default
    // lists the caller's visible set.
    ...
}
```

`NamespaceListQuery { all: Option<bool> }`. Enumeration logic:

- default: `visible_walls(...)` (the same set search spans).
- `all=true` + `ADMIN`: every namespace from `store_stats()`.
- NO doctrine special-casing (contract review round 1, P2 adopted):
  the doctrine wall appears in a listing only when the caller's
  enumeration includes it — membership, own-wall, import visibility,
  or the admin listing. Adding it unconditionally would break the
  listing = search-set invariant the route exists to guarantee.

Counts: from `store_stats()` namespaces (the route may call
`store_stats()` even when `visible_walls` already called it
internally to discover import walls — two cheap calls are
permitted; contract review round 1, P2: the one-call constraint
contradicted the helper's import discovery and is dropped).
`kind_of(slug)` (contract review round 1, P2 adopted — the
server's personal-wall convention is `ns_<principal>_private` for
ANY principal, not only pi hosts): `"global"` for `global`;
`"private"` for any slug ending in `_private`; `"import"` for
`ns_import_*`; else `"shared"`.

Route registration next to `/memories/stats`:

```rust
.route("/namespaces", get(list_namespaces))
```

Description lookup: a `HashMap<String, String>` built from the
`DeclaredNamespace` list — the plumbing from IjimaToml to the handler
mirrors U1's `WallConfig` path (extend `WallConfig` with
`declared: std::collections::HashMap<String, String>`, or an
equivalent single-source approach — pick one, document in the
ambiguity report).

## Tests (api.rs `mod tests`)

1. `namespaces_route_lists_callers_visible_walls`
   - Seed: two memories in the caller's private wall, one in
     `global`, one in a member org wall, one in `ns_import_x`, one in
     a NON-member org wall.
   - GET `/namespaces` (memory:read token, member of the org): the
     member wall, `global`, the import wall, and the private wall are
     listed with correct counts and kinds; the non-member wall is
     ABSENT.
2. `namespaces_route_attaches_declared_description`
   - `app_with_walls` with a declared description for the member
     wall; the entry carries it; undeclared walls have `null`.
3. `namespaces_all_requires_admin_and_spans_everything`
   - memory:read token + `?all=true` → 403; admin token → the
     non-member wall from test 1 IS listed.
4. `visible_search_and_namespaces_agree`
   - Bidirectional equality (contract review round 1, P3 adopted):
     seed one DISTINCT id per expected wall; search `scope=visible`
     with limit above the seed total; assert the hit-id set EQUALS
     the full expected set AND the route's wall set EQUALS the
     expected wall set. One-directional subset checks are not the
     invariant — the listing and the search must agree exactly.
5. `namespaces_kind_of_classifies_non_pi_private_walls`
   - Admin `?all=true`: a stored `ns_elliott_private`-shaped wall
     (any principal's, not the caller's own, not pi-prefixed)
     classifies `"private"` — the suffix convention, not a pattern.
