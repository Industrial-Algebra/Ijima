### `ijima-server/src/backend_surreal.rs` — impls

Implement the three methods in `impl Store for SurrealStore`. Shapes:

```rust
    async fn list_retrieval_events(
        &self,
        namespace: Option<&str>,
        since_unix: u64,
        limit: usize,
    ) -> Result<Vec<RetrievalEvent>> {
        let mut res = self
            .db
            .query(match namespace {
                Some(_) => "SELECT * FROM type::table($t) WHERE namespace = $ns AND ts_unix >= $since ORDER BY ts_unix DESC, rank ASC LIMIT $limit",
                None => "SELECT * FROM type::table($t) WHERE ts_unix >= $since ORDER BY ts_unix DESC, rank ASC LIMIT $limit",
            })
            .bind(("t", RETRIEVAL_LEDGER_TABLE))
            .bind(("since", since_unix))
            .bind(("limit", limit as i64))
            .map(|q| match namespace {
                Some(ns) => q.bind(("ns", ns.to_string())),
                None => q,
            })
            .await
            .map_err(|e| IjimaError::store(format!("ledger list: {e}")))?;
        let rows: Vec<RetrievalEvent> = res
            .take(0)
            .map_err(|e| IjimaError::store(format!("ledger list take: {e}")))?;
        Ok(rows)
    }
```

(If the two-branch query builder is awkward, build the query string
with an `if` before `.query(...)` — the contract is: namespace filter
when given, ts floor, newest-first with rank tiebreak, limit.)

`retrieval_ledger_stats`: one query
`SELECT count() AS total, math::min(ts_unix) AS oldest, math::max(ts_unix) AS newest, array::group(kind) AS kinds, array::group(memory_id) AS mids, array::group(retrieval_id) AS rids FROM type::table($t) [WHERE namespace = $ns]`
— then compute `distinct_memories`/`distinct_retrievals`/`by_kind` in
Rust from the grouped arrays (dedup + count; `by_kind` keys are the
string forms of `RetrievalKind`). If `array::group` on a None-projection
errors on an empty table, guard: empty table → `RetrievalStats::default()`.

`prune_retrieval_events`:
`DELETE FROM type::table($t) WHERE ts_unix < $before RETURN id` —
count the returned ids.

```rust
async fn retrieval_ledger_list(
    principal: AuthPrincipal,
    Extension(store): Extension<Arc<dyn Store>>,
    Query(q): Query<RetrievalListQuery>,
) -> Result<Json<RetrievalLedgerResponse>, ApiError> {
    if !principal.0.may(ijima_core::capabilities::ADMIN) {
        return Err(ApiError::Forbidden);
    }
    let events = store
        .list_retrieval_events(
            q.namespace.as_deref(),
            q.since_unix.unwrap_or(0),
            q.limit.unwrap_or(500).min(10_000),
        )
        .await
        .map_err(internal)?;
    Ok(Json(RetrievalLedgerResponse { events }))
}

async fn retrieval_ledger_stats(
    principal: AuthPrincipal,
    Extension(store): Extension<Arc<dyn Store>>,
    Query(q): Query<RetrievalListQuery>,
) -> Result<Json<RetrievalStatsResponse>, ApiError> {
    if !principal.0.may(ijima_core::capabilities::ADMIN) {
        return Err(ApiError::Forbidden);
    }
    let stats = store
        .retrieval_ledger_stats(q.namespace.as_deref())
        .await
        .map_err(internal)?;
    Ok(Json(RetrievalStatsResponse { stats }))
}

async fn retrieval_ledger_prune(
    principal: AuthPrincipal,
    Extension(store): Extension<Arc<dyn Store>>,
    Query(q): Query<RetrievalPruneQuery>,
) -> Result<Json<RetrievalPruneResponse>, ApiError> {
    if !principal.0.may(ijima_core::capabilities::ADMIN) {
        return Err(ApiError::Forbidden);
    }
    let deleted = store
        .prune_retrieval_events(q.before_unix)
        .await
        .map_err(internal)?;
    Ok(Json(RetrievalPruneResponse { deleted }))
}
```

### `book/src/concepts/retrieval-ledger.md` — FULL FINAL CONTENT

```markdown
# The retrieval ledger

> Since 0.4.2. The ledger records what the read paths actually serve.

Every wake-up, search, and browse response appends one event per
served memory to an append-only ledger. The events carry ids and
metadata only — never memory content and never query text.

## Why

Before 0.4.2 the read paths had no telemetry at all. Which memories
reach agent context, how often, from which wall, and — just as
important — which *never* do: these were unanswerable after the fact.
Policy questions (is the recency stratum admitting too much? does
visible search drown small walls?) need data before they need
opinions. Instrumentation before policy.

## The event

| Field | Meaning |
|---|---|
| `retrieval_id` | Groups all events from one request |
| `kind` | `WakeupRecent`, `WakeupLexicographic`, `WakeupDoctrine`, `Search`, `Browse` |
| `namespace` | The wall the memory was served from |
| `memory_id` | Join key back to the palace |
| `principal` | Who triggered the retrieval |
| `rank` | 0-based position in the served list |
| `similarity` | Cosine similarity (Search events only) |
| `ts_unix` | Unix seconds |

Wake-up strata are recorded separately: the recency stratum (admitted
first, the starvation fix) and the lexicographic fill (importance
order) tag their events distinctly, so stratum distribution is a
one-query question.

## Reading it

Admin-gated:

```sh
# newest 100 events on one wall
curl -H "authorization: Bearer $ADMIN" \
  "http://127.0.0.1:7373/retrieval/ledger?namespace=ns_shared&limit=100"

# aggregate counts
curl -H "authorization: Bearer $ADMIN" \
  "http://127.0.0.1:7373/retrieval/ledger/stats?namespace=ns_shared"

# prune older than a timestamp (returns count deleted)
curl -X DELETE -H "authorization: Bearer $ADMIN" \
  "http://127.0.0.1:7373/retrieval/ledger?before_unix=1770000000"
```

## Design notes

- **Fire-and-logged.** An append failure logs a warning and the read
  still succeeds — observability must not become a new failure mode.
- **Ids, not content.** The ledger joins back to the palace by
  `memory_id`; it never duplicates content or query text.
- **Append-only until pruned.** No process rewrites events; pruning
  is an explicit admin action with a returned count.
```
